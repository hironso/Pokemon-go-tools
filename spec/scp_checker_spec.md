## 1. 概要

ポケモンGOのPvP（トレーナーバトル）において、手持ちの個体のSCPランクとおすすめタグを計算・表示するStreamlitアプリ。

- **デプロイ先**: Streamlit Community Cloud
- **リポジトリ**: `hironso/Pokemon-go-tools`
- **メインファイル**: `scp_checker/app.py`
- **参照ファイル**（形式は各データファイルspecを参照）:
  - `pokedex_numbers.txt`（`master_data/`。種族値データ。形式は `pokedex_numbers_spec.md`）
  - `rank_cheker_input_templete.txt`（`master_data/`。入力テンプレート）

## 2. 入力方法

2種類の入力方法に対応している。

### 2-1. フォーム入力（スマホ向け）

- ポケモン名をテキスト入力（日本語）
- リーグをドロップダウンで選択（S / H / M）
- シャドウチェックボックスで選択（デフォルト：オフ）
- **攻撃IV・防御IV・HP IVは、0〜15の範囲を持つ数値専用の入力欄とする（Rev1.1で変更）**。16進数入力（A〜F等）には対応しない。
  - **変更理由**：従来はA〜Fの16進数入力にも対応するためテキスト入力を用いていたが、スマートフォンでテキスト入力欄をタップすると英数字キーボードが立ち上がり、数字キーボードへの切り替え操作が毎回必要で手間だった。数値専用入力に変えることで、スマートフォンでタップした際に数字キーボードが自動的に表示されるようにする。
  - 範囲外の値（16以上、負の値）は入力を受け付けない。
  - **入力欄の初期状態は「未入力」とする（0を初期値として表示しない）。** 0を初期値にすると、0以外の値を入れたいときに毎回消してから入力する手間が発生するため。
  - **攻撃IV・防御IV・HP IVのいずれかが未入力のまま「追加」ボタンが押された場合、追加は行わずエラーを表示する。** メッセージ：「未入力のIVがあります」（既存の他エラーと同様、`st.error`で表示）。
- 「追加」ボタンで追加済みリストに追加。**追加後、攻撃IV・防御IV・HP IVの入力欄は未入力状態に戻る**（ポケモン名・リーグ・シャドウチェックボックスは保持されたまま）。
- ポケモン名・リーグ・シャドウフラグはフォーム送信後も保持される（連続IV入力が可能）
- **リーグのデフォルト値は`S`（スーパーリーグ）とする。**
- Tab → Tab → Tab → Enter の操作で1個体を追加できる

#### シャドウ判定ルール（フォーム入力）

シャドウチェックボックスと、ポケモン名先頭への`S`付与の2通りでシャドウを指定できる。

| 操作 | 結果 |
|---|---|
| チェックボックスオン ＋ ポケモン名`カメックス` | `Sカメックス`として追加 |
| チェックボックスオフ ＋ ポケモン名`Sカメックス` | `Sカメックス`として追加 |
| チェックボックスオン ＋ ポケモン名`Sカメックス` | `Sカメックス`として追加（二重Sにはならない） |
| チェックボックスオフ ＋ ポケモン名`カメックス` | `カメックス`（通常）として追加 |

### 2-2. ファイルアップロード（PC向け）

- `rank_cheker_input.txt`をアップロード
- テンプレートファイル（`master_data/rank_cheker_input_templete.txt`）のダウンロードボタンあり

#### rank_cheker_input.txtのフォーマット

```
# ポケモン名/リーグ(S/H/M)/攻撃IV/防御IV/HPIV
# シャドウはポケモン名の先頭にSをつける
プクリン/S/1/12/6
プクリン/S/2/14/6
Sプクリン/S/1/13/6
ラッキー/H/15/15/15
```

- リーグ：S=スーパー(1500) / H=ハイパー(2500) / M=マスター
- IV範囲：0〜15
- シャドウ：ポケモン名の先頭に`S`を付ける（例：`Sカメックス`）

> **ファイルアップロード時のIVパースは、10進数として解釈できない値を16進数としてフォールバック解釈する仕様を維持する**（例：`f`→15）。Rev1.1の②（2-1章）はフォーム入力欄のみを対象とした変更であり、`rank_cheker_input.txt`のテキスト形式・パース仕様自体は変更しない。

### 受け入れ条件（入力エラー・共通）

ファイルアップロードされたテキストの各行について、以下のエラーを行番号付きで列挙し、処理を中断する（コメント行`#`・空行は読み飛ばす）。

| エラー内容 | メッセージ形式 |
|---|---|
| `/`区切りが5項目でない | `{行番号}行目: 形式不正 → {行の内容}` |
| リーグ指定がS/H/M以外 | `{行番号}行目: 不正なリーグ → {league}` |
| IVが10進数・16進数のいずれでも解釈できない | `{行番号}行目: IVが数値ではありません → {行の内容}` |
| IVが0〜15の範囲外 | `{行番号}行目: IV範囲不正(0-15) → {行の内容}` |

エラー行が1行でもある場合は、`入力エラーがあります：` の見出しの後に該当エラーを1行1件（`- {エラーメッセージ}`）ずつ列挙し、処理を中断する。

**エラー行は無いが、コメント行・空行しか無く有効な行が1つも無かった場合の警告**：`有効な行がありません。`（この場合も処理を中断する）

計算処理中に発生するエラー（該当した時点で処理を中断）：

| エラー内容 | メッセージ形式 |
|---|---|
| ポケモン名がpokedexに未収録 | `ポケモンが見つかりません: {name}` |
| SCP計算に失敗（該当IVで有効なレベルが1つも無い等） | `計算失敗: {name}/{league}/{iv_a}/{iv_d}/{iv_h}` |

フォーム入力・一括置換時のポケモン名バリデーションエラー：

| エラー内容 | メッセージ形式 |
|---|---|
| 入力・置換後のポケモン名がpokedexに未収録 | `「{name}」はpokedex_numbers.txtに存在しません。`（**{name}はシャドウ判定・S補完を行う前の、入力欄にそのまま入力された文字列とする**。例：`カメックス`とシャドウチェックボックスをオンにして`Sカメックス`が未収録だった場合でも、エラーには入力そのままの`カメックス`を表示する） |
| 攻撃IV・防御IV・HP IVのいずれかが未入力のまま追加操作 | `未入力のIVがあります` |
| ポケモン名が空欄のまま追加操作 | `ポケモン名を入力してください。` |

起動時のデータ読み込みエラー（発生した場合、画面にエラーを表示し以降の処理を停止する）：

| エラー内容 | メッセージ形式 |
|---|---|
| `pokedex_numbers.txt`が見つからない | `pokedex_numbers.txt が見つかりません: {ファイルパス}` |
| テンプレートファイル（`rank_cheker_input_templete.txt`）が見つからない | `rank_cheker_input_templete.txt が見つかりません: {ファイルパス}`（**Rev1.1で追加**。旧実装ではファイルが無い場合エラーを出さずダウンロードボタン自体を表示しないだけだったが、気づかず放置されるおそれがあるためエラー表示に変更する） |

## 3. シャドウポケモンの扱い

- ポケモン名の先頭が`S`かつ`S`を除いた名前が`pokedex_numbers.txt`に存在する場合、シャドウと判定する
- ポケモン名はすべてカタカナのため、先頭`S`は常にシャドウの識別子として機能する
- シャドウの計算ロジックは通常個体と同一（SCPランク・おすすめタグの計算式に違いなし）
- 通常個体とシャドウ個体は**別グループ**として独立してタグ判定される
  - 例：`カメックス/S`グループと`Sカメックス/S`グループはそれぞれ独立してバランス1位・2位などのタグが付与される

## 4. 追加済みリストの操作

- **「追加済みリスト（{件数}件）」の見出しと一覧表示は、リストが1件以上あるときのみ表示する**（0件のときは見出しごと非表示。維持仕様）。
- 「リストをクリア」「計算実行」の2ボタンは、リストの件数に関わらず**常に表示する**（維持仕様）。
- 各行に削除ボタン（✕）
- 「リストをクリア」ボタンで全削除
- **ポケモン名一括置換機能**（Rev1.1でパネル位置を変更）：置換前・置換後のポケモン名を入力して「置換実行」
  - **パネルの配置：「入力方法を選択」の直後・ポケモン名入力欄の直前に配置する。**
  - **パネルの表示条件（Rev1.1で変更）：リストの件数に関わらず、常に表示する。** 旧実装ではリストが1件以上あるときのみパネルが出現していたが、パネルを固定位置（画面上部）に置く以上、リストの件数によって表示・非表示が切り替わるのは分かりづらいため、常時表示に変更する。リストが0件の状態で置換実行を押した場合は、既存の「絞り込み条件に一致する行が0件の場合の警告」（`条件に一致する行がリストに存在しません。`）がそのまま適用され、新しいエラー文言は追加しない。
    - **変更理由**：従来は追加済みリストの下（画面下部）にあり、置換実行後に結果を確認するため画面上部（追加済みリストの表示位置）まで毎回スクロールして戻る必要があり、直感的でなかった。ポケモン名入力欄の直前に配置することで、置換操作と結果確認が近い位置で完結するようにする。
  - 置換後のポケモン名がpokedex未収録の場合はエラー（シャドウ名の場合はS除き名でバリデーション）
  - 置換前のポケモン名がリストに存在しない場合は警告
  - 置換後のポケモン名のシャドウフラグは名前先頭Sの有無で自動再判定される
  - 用途：計算後に間違いに気づいたときにIVを入力し直さずに修正できる

#### 一括置換の詳細ルール・メッセージ

- 置換前・置換後は、それぞれ「ポケモン名」「リーグ」を個別に指定できる（片方のみの指定も可）。リーグは「変更なし」を選べる（デフォルトは「変更なし」）。
- **置換前の名前・リーグの両方が未指定（名前が空欄 かつ リーグが「変更なし」）の場合はエラー**：`置換前のポケモン名またはリーグを指定してください。`
- **置換後の名前・リーグの両方が未指定の場合はエラー**：`置換後のポケモン名またはリーグを指定してください。`
- 置換後のポケモン名を指定した場合、pokedexバリデーションを行う（未収録ならエラー、シャドウ名はS除き名で判定）：`「{置換後の名前}」はpokedex_numbers.txtに存在しません。`
- 置換対象の絞り込みは「名前が空欄なら名前は絞り込み条件にしない（全名前が対象）」「リーグが『変更なし』ならリーグは絞り込み条件にしない（全リーグが対象）」の組み合わせで行う。
- 絞り込み条件に一致する行が0件の場合は警告：`条件に一致する行がリストに存在しません。`
- 置換の適用は「名前が空欄なら名前は変更しない」「リーグが『変更なし』ならリーグは変更しない」（指定した項目のみ書き換える）。
- 置換後のシャドウフラグは、置換後の名前（未指定なら元の名前）に対して先頭`S`の有無で再判定する。
- **成功時メッセージ**：変更した項目のみを列挙する。形式：`名前「{置換前名}」→「{置換後名 または 変更なし}」 / リーグ「{置換前リーグ}」→「{置換後リーグ または 変更なし}」 を{件数}件置換しました。`（名前・リーグのうち指定された方のみを` / `区切りで列挙。片方のみ指定時はその1項目のみ表示）。

#### 追加済みリストが0件のまま計算実行した場合（Rev1.1で追加）

- 追加済みリストが0件の状態で「計算実行」ボタンを押した場合、**警告を表示する**：`有効な行がありません。`（ファイルアップロードモードの警告文言と同一のものを用いる）
- 旧実装ではこの場合、何の反応も無いまま（警告もエラーも出さず）処理が終わっていたが、ユーザーから見て「ボタンを押しても何も起きない」状態は分かりづらいため、Rev1.1で警告を追加する。

## 5. 計算ロジック

### 5-1. SCPランク計算

- 全4096通りのIV（0〜15の3乗）を評価
- 各IVについてレベル1.0〜51.0（0.5刻み）でCP上限以下のSCP最大を探索
- **順位付けの基準は、SCPを整数へ丸める（floor）前の連続値とする（Rev1.1で変更）。** 連続値SCPが大きい順に順位を付与する。
  - **変更理由**：参照しているポケモンGOの外部サイトの実際の順位データ（複数ポケモン・計150件）で検証した結果、当該サイトは表示上こそSCPを整数で表示するが、順位付け自体は丸める前の連続値で行っていることが判明したため、同じ基準に合わせる。
  - 変更前（Rev1.0）は「floor後のSCP降順→攻撃実数値降順」の2段階比較だったが、Rev1.1では連続値SCPの降順のみで順位が一意に定まる（実務上、同一の連続値SCPが2個体以上で完全一致することはない）。
  - 攻撃実数値・防御実数値・HP・CP・floor後SCPそのものの計算式は変更しない。**変更するのは順位付けに使う値のみ**（floor前かfloor後か）。
- `scp_cache.json`は使用しない（リアルタイム計算）
- シャドウ・通常ともに計算ロジックは同一

#### SCP順位の母集団：レベル上限50/51の切り替え（Rev1.2で追加）

**SCP順位（`SCPRANK`列）を計算する際の比較母集団（全4096通り）は、対象個体が`[RB]`タグの対象かどうかで切り替える。**

- **対象個体の最適レベルが50.5または51.0（＝`[RB]`が付く個体）**：レベル上限51まで許容した母集団（全4096通り、各IVの最適レベルは1.0〜51.0で探索）で順位を数える（従来どおり）。
- **対象個体の最適レベルが50.0以下（＝`[RB]`が付かない個体）**：レベル上限50までに制限した母集団（全4096通り、各IVの最適レベルは1.0〜50.0で探索）で順位を数える。

**変更理由**：参照している外部サイトの実データを検証したところ、サイトはレベル上限50までの順位表とレベル上限51までの順位表を別々に持っており、対象個体の最適レベルに応じてどちらの順位表を見るかが決まっていることが判明した（レベル上限51側では、XLアメが無いと到達できない高レベル個体が母集団に加わるため、同じ個体でも相対的な順位が変わる）。

**影響範囲**：
- **変わるのはSCP順位（`SCPRANK`列）の母集団のみ。** CP・攻撃実数値・防御実数値・HP・Levelの表示値は変更しない（対象個体自身の最適レベルは変わらないため、`[RB]`が付かない個体はレベル上限50でも51でも同じ値になる）。
- **おすすめタグ判定（5-2章）の基準は変更しない。** タグ判定はこれまでどおりレベル上限51を基準とする（順位表示とタグ判定基準の前提が異なる状態を許容する。ユーザーとの合意事項）。

### 5-2. おすすめタグ判定

同じポケモン×同じリーグ×同じシャドウフラグの入力個体群の中で判定する。

**Rev1.1より、タグ判定の内部処理もすべて連続値SCP基準に統一する。** 5-1の変更と同じ考え方（判定基準を1種類に揃えることでロジックを単純化し、ランキング表示とタグ付けの基準が食い違わないようにする）による。floor後SCPは、判定には使わず、画面表示にのみ用いる。

**同点個体の並び替え（「攻撃実数値が高い順」の決め方）：攻撃実数値が高い方を選ぶ。攻撃実数値が完全に同じ場合は、連続値SCPが高い方を選ぶ。**（Rev1.0では、floor後SCPが同点になりやすかったため、攻撃実数値→SCP→HP→ランク→入力順という5段階の細かいタイブレークが必要だったが、連続値SCP採用によりHP以降の基準は実務上使われなくなるため廃止する。攻撃実数値・連続値SCPの両方が一致するケースは想定しない。）

#### ★SCP最大
入力個体の中で連続値SCPが最も高い個体（1体のみ）。**連続値SCPが完全に同点の場合は、上記と同じ基準（攻撃実数値が高い方、それも同じなら連続値SCPが高い方）で1体に絞り込む。**

#### ★SCP重視1位・2位
連続値SCP1位の99%以上の中で攻撃実数値が高い順に2体
- 用途：あまり使われないポケモンで攻撃実数値も無視したくない場合

#### ★バランス1位・2位
連続値SCP1位の98.8%以上の中で攻撃実数値最大の個体を基準に、そのSCPの99.75%以上の中で攻撃実数値が高い順に2体
- 2段階絞り込みの理由：SCPがほぼ同じ（99.75%以内）なら攻撃実数値を優先するため。SCPを犠牲にしすぎない設計。
- 用途：多用されるポケモンでミラー対面の同発を意識する場合（最もよく使うタグ）

#### ★攻撃重視1位・2位
連続値SCP1位の98.5%以上の中で攻撃実数値最大の個体を基準に、そのSCPの99.6%以上の中で攻撃実数値が高い順に2体
- 2段階絞り込みの理由：バランスより許容範囲を広げ（99.6%）、より積極的に攻撃実数値を優先する設計。
- 用途：攻撃実数値重視の相手にも同発で勝ちたい場合

#### 1位・2位タグの該当者が足りない場合のフォールバック（維持仕様。Rev1.1で変更しない）

★SCP重視・★バランス・★攻撃重視のいずれも、「〜2体」は**条件を満たす個体が十分にいる場合の上限**であり、常に2体に付くとは限らない。

- **入力個体群の中で、閾値条件を満たす個体が1体しかない場合、1位タグのみを付与し、2位タグは付与しない。**
- **★バランス・★攻撃重視は2段階の絞り込み**（例：バランスなら「98.8%以上」→その中の攻撃実数値最大個体を基準に「99.75%以上」）を行う。**1段階目の閾値を満たす個体が1つも無い場合**、フォールバックとして「入力個体群の中で連続値SCPの順位（5-1章）が最も良い1体」を基準個体として採用し、その基準個体のSCPから2段階目の閾値絞り込みを行う。
- **★SCP重視は1段階の絞り込みのみ**。閾値を満たす個体が1つも無い場合は、同様に「入力個体群の中でランクが最も良い1体」を候補として1位タグのみ付与する。
- 上記いずれの場合も、絞り込み後の候補が2体以上なら「攻撃実数値が高い順」（5-2章冒頭のタイブレーク規則）で上位2体に1位・2位を付与する。

#### 設計の背景
- SCPは攻撃×防御×HPの積のため、SCP差は実戦に複合的な影響を与える
- ミラー対面では攻撃実数値が高い方がスペシャル技同時発動時に先制できる
- 98.8%・98.5%・99.75%・99.6%の数値は経験則による設定であり理論的根拠はないが、方向性は実戦理論に合致している
- これらのパーセンテージ算出の基準値（「連続値SCP1位」＝全4096通り中の連続値SCP最大値）も、Rev1.1では連続値ベースで算出する

#### `[RB]`タグ（維持仕様。Rev1.1で変更しない）

- ★タグとは別に、**個体のレベルが50.0を超える場合**、出力行のタグ欄の先頭に `[RB]` を付与する。
- おすすめタグ（★〜）が1つも付かない場合でも、レベルが50超なら `[RB]` のみは出力される。
- タグ欄の内容は「`[RB] ` + ★タグをスペース区切りで連結したもの」（`[RB]`が無い場合は★タグのみ）。

#### 複数の★タグが付いた場合の並び順（Rev1.1で明文化。表示結果は現行と変わらない）

1個体に複数の★タグが付いた場合、**タグの判定基準となるSCPの閾値（%）が高いグループを左から並べる。同じタググループ内では1位→2位の順とする。** 固定の並び順は以下のとおり（左が最優先）。

1. `★SCP最大`（基準100%）
2. `★SCP重視1位`（基準99%）
3. `★SCP重視2位`
4. `★バランス1位`（基準98.8%）
5. `★バランス2位`
6. `★攻撃重視1位`（基準98.5%）
7. `★攻撃重視2位`

> 従来実装は文字列のUnicodeコードポイント順で偶然この並びになっていたが、Rev1.1では「SCP基準が高いグループが左」という意図した固定順位として実装する（見た目の出力結果は変わらない）。

- 空行の挿入判定は「直前の1行」とだけ比較する（名前・リーグ・シャドウのいずれかが直前行と異なれば空行を挿入）。同じポケモン・リーグ・シャドウの行が離れた位置に複数回現れる場合を考慮した、まとめ直しやソートは行わない。
  - 例：`プクリン`→`プクリン`→`ラッキー`の順で入力すればプクリンの2行はひとまとまりで出力されるが、`プクリン`→`ラッキー`→`プクリン`の順で入力すると、プクリンのブロックが2つに分かれて出力される（間にラッキーのブロックを挟む）。これは意図した仕様であり、自動的なグルーピング・ソートは行わない。
  - **おすすめタグ判定（5-2章）はこの並び順の影響を受けない**（判定は入力順序に関わらず、同じポケモン×リーグ×シャドウの個体群をグループ化して行うため）。影響が出るのは出力の見た目（ブロックの分かれ方）のみ。
- 入力表示は`ポケモン名/攻撃IV/防御IV/HPIV`形式（リーグはブロック単位で同一のため省略）
- **画面表示・output.txtの「SCP」列は、従来どおり整数（floor後の値）で表示する。** 順位付け・タグ判定の内部で連続値を使うことと、表示を整数にすることは矛盾しない（5章参照）。
- ダウンロードボタンで`output.txt`として保存可能

#### 列幅・整列の規則（固定仕様）

- 入力表示列（`ポケモン名/攻撃IV/防御IV/HPIV`）の幅は、その回の全結果行のうち最長の文字数＋2。以降の列はこの幅に揃えて左詰めする。
- ヘッダー行の先頭空白幅は、入力表示列の幅＋5。ヘッダーの各列見出しは `League`（7桁）・`SCPRANK`（8桁）・`SCP`（4桁）・`ATK`（6桁）・`DEF`（6桁）・`HP`（3桁）・`CP`（4桁）・`Level`（5桁）、いずれも左詰め、列間は半角スペース1つ。
- 各データ行は「入力表示（左詰め、上記幅）」+「League（左詰め7桁）」+ 半角スペース + 「SCPRANK（4桁ゼロ埋め＋半角スペース5つ）」+「SCP（左詰め4桁）」+ 半角スペース + 「ATK（左詰め6桁、小数点以下2桁）」+ 半角スペース + 「DEF（左詰め6桁、小数点以下2桁）」+ 半角スペース + 「HP（左詰め3桁）」+ 半角スペース + 「CP（左詰め4桁）」+ 半角スペース + 「Level（左詰め5桁、小数点以下1桁）」の順。
- タグ欄（`[RB]`・★タグ）が1つ以上ある行は、上記データ部分の後に半角スペース2つを置いてからタグ欄を出力する。タグが無い行はタグ欄自体を出力しない。
- タグ欄の内容は「`[RB] `（該当時のみ）+ ★タグをスペース区切りで連結」（5-2章参照）。

## 10. 制約

恒久的な前提を以下にまとめる。

- **リポジトリ構成（フォルダ・ファイル配置）の正は本仕様書ではなく `spec/repository_overview.md` とする。** 本仕様書はファイル構成図を持たない。ソフトウェアの層分け（features/library/esal等への分割方法）も本仕様書では規定せず、実装（Claude Code）の判断に委ねる。
- **参照データファイルのファイル形式の正は、それぞれのデータファイルspecとする。** `pokedex_numbers.txt` → `pokedex_numbers_spec.md`。本仕様書では形式を規定しない。本アプリからの使い方（読み取り後の解釈）は3章に従う。
- **SCPランキング・おすすめタグ判定は、連続値SCP（floorする前の値）を基準とする。** floor後のSCPは画面表示にのみ使い、判定には使わない（5章）。攻撃実数値・防御実数値・HP・CP・floor後SCPそのものの計算式は変更しない。
- **攻撃IV・防御IV・HPIVのフォーム入力は数値専用（0〜15）とし、16進数入力には対応しない。初期値は未入力とし、未入力のまま追加操作をした場合はエラーとする**（2-1章）。
- **ポケモン名・リーグ一括置換パネルは、入力方法選択の直後・ポケモン名入力欄の直前に配置する**（4章）。
- **データファイル（pokedex・テンプレート）が見つからない場合は、画面にエラーメッセージを表示する**（2章）。
- **画面表示文言（見出し・ボタン・プレースホルダ・メッセージ）は9章の記載どおり固定する**。
- **結果テーブルの行はソートせず入力順のまま出力し、空行挿入は直前行との単純比較で行う**（6-2章）。
