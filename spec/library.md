## 1. この層は何か（責務）

`library` は、**2 つ以上のアプリ／ツールで共通して使う純粋ロジック**を置く層である。
「純粋」とは、Streamlit・ファイル読み込み・ネットワーク等の外部依存を持たず、必要なデータはすべて引数で受け取り、同じ入力に対して常に同じ出力を返すことを指す。

- **場所**: `src/library/`
- **依存の向き**: `features → library / esal`。features（各アプリの純粋ロジック層）は library を呼んでよい。library は esal（ファイル読み込み層）を呼んでよい。**逆向き（library → features）は禁止**。
- **呼び出し側**: 各アプリの features 層、および `tools/` の各ツール。

### なぜ置くか

同じ処理が複数箇所に別実装で存在すると、片方だけ直したときに静かに挙動がずれ、結果が食い違う。共通化の目的は行数削減（DRY）ではなく、**「同じ処理は必ず同じ結果になる」ことの保証**である。したがって library に置くのは、ずれると結果の正しさが壊れる中核処理に限る。

### 収録の基準

- **2 つ以上のアプリ／ツールが必要とする**こと。1 箇所でしか使わない処理はそのアプリ側に置く。
- **純粋**であること（上記の定義）。ファイル読み込みが必要なら、その部分は esal に置き、library は読み込み済みのデータを引数で受け取る。

### 分割の方針

当面 library は 1 フォルダ・1 仕様書（本書）で運用する。収録する部品が増え、本書が見通しにくくなった時点で、部品ごとの分割を検討する。

## 3. expand_targets

### 3.1 役割

入力ポケモン 1 種と、その O/M/L 指定を受け取り、**実際に計算・キャッシュ対象とすべきポケモン種名のリスト**を返す。進化ファミリーの段構造をもとに、指定（本人／中間進化／最終進化）に対応する段のメンバーへ展開する。

この展開は、`iv_strings_generator`（アプリ本体）と `slim_cache_builder`（キャッシュ生成ツール）の両方が必要とする、まったく同じ処理である。両者がこの 1 部品を呼ぶことで、**アプリが参照する種と、キャッシュが生成する種が常に一致する**。

### 3.2 入出力

**入力（引数）**

| 引数 | 内容 |
|---|---|
| 入力ポケモン名 | 展開の起点となるポケモン名。 |
| 対象指定 | `O`／`M`／`L` の指定（複数可、重複は除去済みを想定）。 |
| 段構造の進化マップ | 段構造を保持した進化マップ。**段のリストであり、各段は同一段メンバー名のリスト**。esal の `load_evolution_map_staged` が返す形式（読み込みの正は esal、進化マップのファイル形式の正は `evolution_map_spec.md`）。 |

**出力（返り値）**

- 展開後のポケモン種名のリスト。
- **重複は初出優先で除去**する。
- 順序は「対象指定の指定順 → 各段はマップ収録順」とする。

### 3.3 展開ルール（正）

段の数え方と分岐の扱いを次のとおり定める。**この定義を、O/M/L 展開の唯一の正とする。**

- **段の数え方**：ファミリーの段数は、進化マップの**カンマで区切られた段の数**で数える。スラッシュ `/`（同一段の分岐）は段数に影響しない。
  - 例: `ラルトス,キルリア,サーナイト/エルレイド` は 3 段。`ヤドン,ヤドラン/ヤドキング` は 2 段。
- **展開の対象**：
  - `O`：入力したポケモン本人。
  - `M`：ファミリーが 3 段以上なら 2 番目の段、2 段なら最終進化の段（＝ `L` と同じ）。
  - `L`：最終進化の段（最後の段）。
- **分岐の扱い（重要）**：指定した段に分岐（スラッシュ）が複数あるときは、**その段の分岐先をすべて対象にする**。
- **未収録の扱い**：進化マップに収録されていないポケモン（進化しないポケモン）は、`O` として本人のみを対象にする。

### 3.4 判断表

| 指定 | 段数 | 対象にする段 | 分岐がある場合 |
|---|---|---|---|
| O | － | （段によらず）本人のみ | － |
| M | 3 段以上 | 2 番目の段 | その段の全枝 |
| M | 2 段 | 最終段（= L と同じ） | その段の全枝 |
| L | － | 最終段 | その段の全枝 |
| O/M/L | 未収録 | 本人のみ | － |

### 3.5 検証済み例

| 入力名 | 段構造（例） | 指定 | 出力 |
|---|---|---|---|
| イーブイ | イーブイ ／ シャワーズ・サンダース・ブースター・エーフィ・ブラッキー・リーフィア・グレイシア・ニンフィア | L | シャワーズ, サンダース, ブースター, エーフィ, ブラッキー, リーフィア, グレイシア, ニンフィア（最終段 8 枝すべて） |
| ヤドン | ヤドン ／ ヤドラン・ヤドキング | L | ヤドラン, ヤドキング（2 段なので最終段。両枝） |
| ヤドン | ヤドン ／ ヤドラン・ヤドキング | M | ヤドラン, ヤドキング（2 段なので M ＝ L） |
| ラルトス | ラルトス ／ キルリア ／ サーナイト・エルレイド | L | サーナイト, エルレイド（最終段の両枝） |
| ラルトス | ラルトス ／ キルリア ／ サーナイト・エルレイド | M | キルリア（3 段なので 2 番目の段。分岐なし） |
| フシギダネ | フシギダネ ／ フシギソウ ／ フシギバナ | M | フシギソウ（3 段の 2 番目の段） |
| ベロリンガ | （進化マップに収録あり／なしのいずれか） | O | ベロリンガ（本人のみ） |
| （未収録の単体ポケモン） | 進化マップに未収録 | L | 本人のみ（未収録は O 扱い） |

### 3.6 受け入れ条件

- `O`／`M`／`L` それぞれが 3.3・3.4 のとおりに展開されること。特に、指定した段が分岐しているとき、**その段の全枝が漏れなく出力される**こと。
- 未収録のポケモンは、指定に関わらず本人のみが出力されること。
- 出力に重複が無く（初出優先で除去）、3.2 の順序規則に従うこと。
- 同一の入力（名前・指定・段構造マップ）に対して常に同じ出力を返すこと（純粋関数）。

## 4. 制約

恒久的な前提を以下にまとめる。

- **進化マップのファイル形式の正は `evolution_map_spec.md`**（カンマ＝段、スラッシュ＝同一段の分岐）とする。本書は形式を規定しない。
- **進化マップの読み込み（段構造への変換）の正は esal の `load_evolution_map_staged`** とする。library の部品は、読み込み済みの段構造を引数で受け取り、ファイルを直接読まない。
- **O/M/L 展開の正は本書（3章）とする。** 各アプリ仕様書は、O/M/L 展開について本書を参照し、独自に定義し直さない。
- library には、2 つ以上のアプリ／ツールが共通して使う純粋処理のみを置く（1章の収録基準）。
- 依存の向きは `features → library / esal` を守り、逆向きの依存を作らない。
